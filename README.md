# 産業保健リサーチブリーフ

産業医・研究者が、重要な研究と制度の変化を把握し、次の研究課題を考えるためのエージェントです。日本語のHTMLブリーフを作成し、設定後はGmailなどに毎日配信できます。

## 今の初期版でできること

- Europe PMCから医学・公衆衛生・産業保健の論文と抄録を取得。ギグ・配送就業者、過重労働、メンタルヘルス、デジタルヘルス、中小企業の健康経営を優先します。
- Crossrefから経済・経営・労働分野も含む関連学術情報を検索します。分野を限定した検索ではなく、取得後のキーワード判定で仕事と健康の双方に関連する資料を選びます。
- 対象誌は `research_bot/journals.py` で管理します。JOEM・JOH・SJWEH・OEMを中核に、Lancet・JAMA・NEJM系列、その他の指定誌から選びます。Frontiers・BMC系は通常配信の対象外です。IFの最新値による自動判定ではありません。
- 論文10本の末尾に、国内の指針・法令改正・専門家会議・労働安全衛生ニュースを最大5件追加します。厚労省新着、指定の審議会一覧と会議資料PDF、NHK RSSを使い、概要・産業保健への意味・段階と注意点・原文URLを示します。[国内動向の仕様](docs/DOMESTIC_BRIEF.md)に収集範囲を記載しています。
- 1日最大10本、最重要3件を冒頭に示し、目的・方法・結果・限界・産業保健への示唆を日本語で要約します。短い回は無理に件数を埋めません。
- DOI / PubMed / 公式ページのURLを必ず紐付けます。AIにはURLを作らせません。
- 1日10本に収まらない対象論文は、公表日から最大30日まで繰り越します。期限と待機日数を選定に反映し、繰越・期限超過数も表示します。[選定方針](docs/SELECTION_POLICY.md)を参照してください。
- 事実と区別した「研究の芽」を最大2件提案します。新規性や採択可能性を保証するものではありません。
- SQLiteに収集・送信履歴を保存し、同じDOI・正規化した題名の再配信を防ぎます。
- 過去90日間に取得したテーマ別件数を週単位で保存します。これは取得履歴であり、分野全体の研究量の推定ではありません。

Python 3.11以上（推奨3.12）。外部Pythonパッケージは不要です。Linux/macOS用です。

会議資料PDFの文字抽出には `pdftotext`（poppler-utils）が必要です。このクラウド環境では利用可能で、GitHub Actionsにも不足時の導入処理を用意しています。画像PDFのOCRには未対応です。

## まず表示を試す（APIキー不要・メール送信なし）

リポジトリのルートで実行します。

```sh
python -m research_bot.cli doctor
python -m unittest discover -s tests -v
python -m research_bot.cli run --demo
```

`output/demo/latest.html` をブラウザで開くと表示見本を確認できます。**全件が架空のデータで、固定の日本語文章です。実際の最新論文やAI要約の検証結果ではありません。** デモは実データと別のDBに保存し、メール送信を禁止しています。

## 実際の情報で試す

環境設定に `RESEARCH_LLM_API_KEY` を安全に登録します。OpenAI APIの利用料金が発生します。モデルの初期値は `gpt-4.1-mini`、変更は `RESEARCH_LLM_MODEL` で指定します。キーをチャット、Git、`config.toml` に書かないでください。

```sh
# 実情報取得 + 日本語要約。初期値は30日間。メール送信なし。
python -m research_bot.cli run

# AIなしで、実際に取得した書誌情報・原文の抄録だけを確認する場合
python -m research_bot.cli run --no-ai
```

結果は `output/latest.html` と `output/latest.json`、履歴付きの `output/brief-*.html` / `.json` に保存します。プレビューだけでは送信済みにしません。繰り返しのプレビューは要約APIを再呼び出すため料金がかかります。

読みやすいMarkdown版も `output/latest.md` に保存します。`output/pilot/latest.html` / `latest.md` がある場合は、このチャットのAIが取得済みの実際の抄録から作った初回試読版です。APIを使った自動要約の動作実績とは別です。

許可が必要な接続先：

| 接続先 | 用途 |
|---|---|
| `www.ebi.ac.uk` | Europe PMC検索・抄録 |
| `api.crossref.org` | 学際的な文献メタデータ |
| `www.mhlw.go.jp` | 厚生労働省の新着フィード |
| `www3.nhk.or.jp`, `news.web.nhk` | 公開ニュースRSS・報道ページ |
| `api.openai.com` | 日本語要約・研究仮説 |
| `api.resend.com` | 設定後のメール送信 |

403や接続拒否は、APIキーより先に環境のネットワーク許可を確認してください。TLS検証を無効化しないでください。

## Gmailへメールを届ける設定

Gmailは受信先として利用します。送信はHTTPSで利用できるResendを使用します。Gmailのパスワードは不要です。

| 変数 | 設定内容 |
|---|---|
| `RESEARCH_LLM_API_KEY` | OpenAI APIキー（要約） |
| `RESEARCH_MAIL_API_KEY` | Resend APIキー（送信） |
| `DIGEST_TO` | 受信するGmailなどのアドレス |
| `MAIL_FROM` | Resendで利用を許可された送信元アドレス |
| `RESEARCH_LLM_MODEL` | 任意。初期値 `gpt-4.1-mini` |

Resendの本運用では送信ドメインの認証が必要です。テスト用送信元はResend側で許可された宛先に限られます。任意のGmailアドレスを送信元に指定するだけでは送れません。Resendの設定・料金は利用前に確認してください。

```sh
# まずプレビューを確認してから実行。実メールを1通送信します。
python -m research_bot.cli run --send
```

メールサービスの受付成功と受信箱への到達は別です。初回は迷惑メールも含めて着信を確認してください。

### 送信の安全性と再試行

- 明示的に `--send` を付けた場合だけ送信します。
- 有効化した情報源のいずれかが失敗した場合、または要約を検証できない場合は、資料一覧を保存して終了コード2で終了し、送信しません。
- 抄録がない場合は、AIの返答にかかわらず方法・結果などを「未取得」に置き換えます。
- `data/outbox.json` に送信内容と一意のキーを保存します。タイムアウト後も同じ内容・同じResendの冪等キーで再試行します。
- 保留メールがある場合は、それを処理してその回を終了します。新しいメールを重ねて送りません。
- Resendの冪等キーの有効期間を超えないよう、23時間以上保留されたメールは自動再送しません。Resendで送信履歴を確認し、復旧してください。確認せずoutboxやDBを削除しないでください。
- APIキーはDB・出力・ログに保存しません。outboxには宛先と本文が入るため、`data/` を公開しないでください。

## 毎日、日本時間の朝7時に最大10本を自動配信

今回の10日間試用の具体的なGitHub設定は [GitHubでの試用開始手順](docs/GITHUB_TRIAL_SETUP.md) を参照してください。初回は2026年10月18日に送信済みで、固定終了日は同月27日です。10月28日以降は送信しません。

現在は10日間の試用設定です（`config.toml` の `trial_days = 10`）。初めてメールサービスが送信を受け付けた日を日本時間で1日目として、10日目まで配信し、11日目から送信を停止します。APIや宛先の準備中には期間が始まりません。送信失敗・新着なしの日も、開始後は10日間に含みます。同日の追加送信も抑止します。試用終了後の継続は別途設定を変更する必要があります。

試用期間と送信済み履歴は `data/` に保存します。削除すると期間がリセットされるため、永続ディスクで保持してください。GitHub Actionsのキャッシュは失われることがあるため、10日間の停止を確実に運用するには永続ストレージが必要です。

`.github/workflows/digest.yml` を用意しています。GitHub Actionsの実行には、コードをGitHubに保存し、Actionsを有効にする必要があります。このクラウド環境でコードを作っただけでは、定期実行は始まりません。

1. GitHubのリポジトリ設定 → Secrets and variables → Actionsで、上表のキーとメールアドレスをSecretsに登録します（モデルだけは任意のVariables）。秘密値はコードに書きません。
2. Actionsの `Occupational health research brief` を手動実行し、実メールの着信を確認します。
3. 毎日22:00 UTC（日本時間で翌朝7:00）に起動し、日本時間で未配信の日に最大10本を配信します。実行遅延による数分の差で配信日を逃さないよう日付で判定します。新着がない日は送信しません。

GitHubのスケジュールは定刻実行の保証がなく、遅延や休止があり得ます。特に公開リポジトリでは非活動によるスケジュール停止に注意してください。

履歴はGitHub Actionsのキャッシュに保存します。**キャッシュの退避・削除後は履歴が失われ、既報の再送や配信間隔のリセットが起こり得ます。** 個人での試用向けです。継続的な本運用には永続ディスクを持つサーバーやマネージドDBへの移行を推奨します。outboxに宛先があるため、原則として非公開リポジトリで利用してください。

永続ディスクがあるLinuxサーバーなら、環境変数を安全に設定した上で、同じ作業ディレクトリ・`data/`を使って毎日7時（Asia/Tokyo）に `python -m research_bot.cli run --send --scheduled` を起動できます。キーをcronのコマンドに直書きしないでください。

## 収集・解釈の限界

- 論文の全文は取得しません。論文は抄録、国内動向は取得できた公式ページ・会議資料PDF・報道の抜粋を根拠に、原文確認への入口を作ります。資料の取得範囲と未取得を表示します。
- Europe PMCは毎回、対象誌の公表日を基準に過去30日を再検索します。Crossrefの補助検索は索引更新を基準に7日重ねて再検索します。最終的な配信候補は、取得日ではなく公表日から30日以内に限定します。
- Europe PMCではJOEM・JOH・SJWEH・OEMを個別に検索し、他の系列誌も8誌以下の組ごとに検索します。各検索は初期値50件×2ページ、Crossrefは各検索50件までです。上限到達を表示します。取得件数は重複除外前で、全件収集は保証しません。
- Crossrefの検索は広く、重複や無関係な情報が混じります。キーワード選定は試用段階のルールであり、関連研究を見逃す場合があります。研究者のフィードバックで調整する前提です。
- 主要医学誌も検索対象ですが、5大誌の全号監視ではありません。論文の全文取得、WHO/ILOの個別フィード、海外ニュース、研究助成の公募情報は未実装です。国内は厚労省とNHKの限定的な巡回であり、国内全媒体を網羅するものではありません。
- 厚労省の新着フィードだけでは、全ガイドライン・過去の発表を網羅できません。公式発表の掲載が法令・指針の発効を意味するわけではありません。
- プレプリントは区別し、取得できた撤回情報は除外します。ただし査読・撤回状態を網羅的に確認する機能ではありません。
- 書誌上の同一タイトルやDOIは重複除外できますが、題名が変わったプレプリントと正式論文の対応付けは完全ではありません。
- AI要約と研究仮説には誤りがあり得ます。申請書や論文に使う場合は原文と追加文献検索で確認してください。

## 構成とテスト

`research_bot/journals.py`（対象誌）、`queue.py`（最大30日の繰越）、`sources.py`（収集）、`core.py`（選定）、`store.py`（履歴）、`summarize.py`（根拠付き日本語要約）、`render.py`（HTML）、`mail.py`（送信）、`cli.py`（実行）に分けています。

```sh
python -m unittest discover -s tests -v
```

テストはネットワーク・有料API・実メールを使いません。パーサー、選定、出典対応、未取得データ、失敗時の動作、配信間隔、再送を検証します。外部APIの実接続・日本語要約の品質・メールの着信は、設定後に実データで別途確認する必要があります。
