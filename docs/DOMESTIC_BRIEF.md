# 国内動向5件

論文10本・研究の芽の後、ブリーフの末尾に「国内動向」を最大5件掲載します。各項目は「概要」「産業保健への意味」「段階・注意点」と原文URL、取得した会議資料へのリンクで構成します。通常は各250〜400字程度を目安とします。

## 情報源

- 厚生労働省の新着フィード：日本の指針・ガイドライン・マニュアル、法令改正に関する発表、労働安全衛生の統計・行政発表。
- 利用者指定の審議会一覧 `https://www.mhlw.go.jp/stf/shingi/indexshingi.html` と、そこからたどる労働基準局の検討会等の一覧。
- 安全衛生分科会、化学物質管理、ストレスチェック、健診、個人事業者、労災保険、労働基準関係法制などの会議一覧を優先して巡回。
- NHKの公開ニュースRSSから、労働災害、過労、職場の健康・安全等に関する報道。全報道機関・全記事を検索する方式ではありません。

国内の学会・自治体等の全ガイドライン、官報・e-Gov全法令、地方労働局の全発表、NHKの全過去記事を網羅する機能ではありません。

## 会議の内容と制度の段階

会議一覧の開催日と議題を読み、開催済みで議事録・資料等へのリンクがある会議を候補にします。議事録があれば優先し、会議ページの本文と資料PDFを取得します。資料は1会議につき最大2点、各PDF冒頭最大12頁、文字数にも上限を設けた抜粋です。資料番号の大区分が異なるものを優先し、議事次第・表紙・名簿だけに偏らないようにします。

PDFの文字抽出には `pdftotext`（poppler-utils）が必要です。このクラウド環境では利用可能です。GitHub Actionsには、不足時に公式Ubuntuパッケージから導入する処理を追加しています。画像PDFのOCRには未対応で、取得失敗・抽出失敗と取得できた資料を明示します。原文全体や会議全体を確認したとは扱いません。

開催案内だけの情報は、開催済み会議の概要枠を埋めるために使いません。議題や案が掲載されたこと、審議・答申、法令の公布・施行は別の段階です。ガイドラインの推奨を法的義務とは書かず、日付・対象・義務が取得資料から確認できない場合は未確認と明記します。

## 選定・重複・少ない日

公表日から30日以内を原則とし、会議一覧から得た項目では会議開催日を使って、その日付の意味を表示します。資料公開日と混同しません。未配信の候補からカテゴリの広がりと産業保健への関連性を考慮して選び、5件を超えた候補は履歴に残します。

同じ公式ページを新着フィードと会議一覧の両方で取得しても、URL・DOI・題名で重複除外します。実メールの受付確認後に論文と国内動向の双方を送信済みにします。プレビューだけでは送信済みにしません。

情報源に該当記事がないことと、取得失敗は区別します。候補が5件に満たない日は件数を示し、既報・無関係な情報・架空のニュースで穴埋めしません。ニュース、指針、法令、会議が毎回1件ずつ入る保証はありません。

## 実行

```sh
python -m research_bot.cli doctor
python -m research_bot.cli run --no-ai
python -m research_bot.cli run
```

`--no-ai` は取得本文・概要の抜粋だけを表示します。日本語の自動要約には `RESEARCH_LLM_API_KEY` が必要です。国内動向の要約は論文とは別に短いAPIリクエストで生成し、すべての出典IDを照合します。国内動向の要約が欠落・不正なら実メールは送信しません。

収集設定は `config.toml` の `mhlw`, `mhlw_meetings`, `domestic_news`, `domestic_max_items`（最大5）、`meeting_indexes`（初期12）、`domestic_max_pages`（各情報源の詳細取得上限、初期12）です。巡回上限に達した場合は表示します。
